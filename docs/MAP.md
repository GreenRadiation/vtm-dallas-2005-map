# Как устроена карта

## Файлы

| Файл | Что внутри |
|---|---|
| `index.html` | Оболочка страницы: шапка с кнопками, карта, карточка, подвал. Leaflet 1.9.4 с cdnjs и шрифты. |
| `assets/style.css` | Стили, включая цвета слоёв карты. Цвета — токены в `:root`, есть тёмная тема. |
| `assets/app.js` | Логика сайта: масштабы и режимы, карточки, поиск, личные пометки, ссылки. |
| `data/map.json` | Тексты и метки регионов. Пишется руками. |
| `data/areas.tsv` | Крупные области: id и название. |
| `data/cities.tsv` | Города по переписи 2000 года: русское название и область. |
| `data/seeds.tsv` | Районы: опорные точки (центры ячеек). |
| `data/natural.tsv` | Озёра и большие парки, которые становятся отдельными регионами. |
| `data/seeds3.tsv` | Ручная нарезка детального масштаба (сейчас — центр Далласа). |
| `data/geo/*.geojson` | Готовая геометрия: `l1` (области), `l2` (части областей), `l3` (районы), `l4` (секторы), `labels`, `roads`, `water`, `rail`, `green`. Собирается скриптом, руками не правится. |
| `data/geo/regions.txt` | Список районов с площадью и числом секторов — для проверки глазами. |
| `data/legacy/grid-2005.json` | Тексты старой карты в клетку. На сайте не показываются, это справочный материал для новых описаний. |
| `data/raw/` | Скачанные сырые данные, в репозиторий не попадают. |
| `tools/` | Скрипты сборки (Python 3.11, нужны `shapely` ≥ 2.1, `pyshp`, `numpy`). |

## Сборка геометрии

```
pip install shapely pyshp numpy
python tools/fetch.py     # скачать OSM и перепись в data/raw/ (один раз)
python tools/build.py     # собрать data/geo/*
python tools/geocheck.py  # необязательно: сверить точки районов с геокодером OSM
```

Скрипты запускаются из корня репозитория. `build.py` работает около 20 секунд и печатает предупреждения, если что-то легло не так (ручной сектор не применился, осталась дыра).

### Четыре масштаба

Регионы устроены как провинции в стратегиях: простые почти выпуклые многоугольники с общими прямыми границами. Точная городская черта и улицы для границ не используются — это игровая карта, а не топография.

1. **Готовые регионы.** Озёра и парки из `natural.tsv` и аэропорты (точки `@aero:` в `seeds.tsv`) берутся из OSM и сильно сглаживаются. Остальная суша — «поле» для ячеек.
2. **Районы (`l3`, мелкий масштаб)** — ячейки Вороного вокруг точек. Точки — это районы из `seeds.tsv` (стоят на месте) плюс по точке в центре каждого города без своих районов, плюс дополнительные точки, которые k-средних расставляет так, чтобы ячейки в области были примерно равной площади: центр 5 км², город 11, пригород 20, сельская местность 45 (`T_DISTRICT`). Область каждой точки определяется по сглаженной городской черте 2000 года. Дополнительные ячейки называются по ближайшему району или городу и стороне света: «Карролтон, юг», id — `<район>-s`.
3. **Части областей (`l2`, средний масштаб)** — группы соседних районов одной области (k-средних по центрам районов, связность проверяется), размер около 25 / 45 / 70 / 160 км² (`T_ZONE`). Название — по двум самым крупным именованным районам («Лейквуд и Каса-Линда»), id — `<область>.<направление>`.
4. **Области (`l1`, крупный масштаб)** — объединение районов по полю «область».
5. **Секторы (`l4`, детальный масштаб)** — ячейки Вороного внутри района: 1,4 / 3 / 5 / 15 км² (`T_SECTOR`), либо по ручным точкам из `seeds3.tsv`. Названия «<район> — север» и т. п., id — `<район>.<направление>`.

Все уровни вложены друг в друга, границы у них общие. Соседние области раскрашены разными цветами (6 тонов), соседние регионы внутри — разными оттенками (3 оттенка).

### Как поправить границу

Подвинь точку района в `seeds.tsv` или добавь новый район — соседние ячейки перестроятся. Для детального масштаба — строки в `seeds3.tsv`. Потом пересобери. Id дополнительных ячеек и секторов (`-s`, `.n`) зависят от геометрии и после правок могут сдвинуться; тексты в `map.json` для них придётся перенести.

### Анахронизмы

В начале `tools/build.py`: `ANACHRONISM_ROADS` (Margaret Hunt Hill Bridge, Chisholm Trail Parkway, все экспресс-полосы TEXpress, платные продолжения SH 360), `ANACHRONISM_PARKS` (Klyde Warren Park и новые скверы даунтауна), `anachronism_way` (западное продолжение платной дороги Буша по SH 161 и восточное до Роулетта), `LATER_NAMES` (поздние названия дорог). Из линий DART оставлены Красная и Синяя, Синяя обрезана до Ledbetter и Downtown Garland. Lake Viridian (2010-е) не включён в природные регионы.

## Сайт

### Режимы и масштабы

Кнопки в шапке:

- **Районы / Дороги.** В режиме районов кликаются регионы, дороги бледные и не кликаются. В режиме дорог регионы — бледный фон крупных областей, а фривеи и большие улицы яркие, с названием при наведении и карточкой по клику.
- **Авто / Крупный / Средний / Мелкий / Детальный.** Показан только один масштаб регионов, без смешения. В «Авто» он выбирается по приближению: до zoom 10.75 крупный, до 11.6 средний, до 12.6 мелкий, дальше детальный (`AUTO` в `app.js`); подчёркнутая кнопка показывает, какой масштаб выбран автоматически. Поверх тонких границ текущего масштаба рисуются толстые границы старших. Зум плавный, шаг 0.25.

Подписи ставятся без наложения: сначала важные, остальные — если есть место. В DOM лежат только видимые подписи, размер подписи считается через canvas `measureText`, без перерисовки страницы.

### Формат data/map.json

```json
{
 "schema": 4,
 "updated": "2026-10-27",
 "areas": {"dal-east": {"marker": "", "label": "", "summary": "", "details": "…", "more": "", "notes": ""}},
 "zones": {"dal-east.n": {"details": "…", …}},
 "districts": {"prestonhollow": {"marker": "important", "label": "Элизиум", "details": "…", …}},
 "sectors": {"anatole": {"marker": "important", "label": "Отель Барона", …}}
}
```

Ключи — id из `l1` (areas), `l2` (zones), `l3` (districts), `l4` (sectors). Названия берутся из геометрии, а не из этого файла.

| Поле | Значение |
|---|---|
| `marker` | `""`, `"haven"`, `"ally"`, `"hostile"`, `"important"`. Метка района видна пунктиром на его части области и на его секторах. |
| `label` | Подпись метки. |
| `summary` | Необязательная строка под заголовком. |
| `details` | Описание. Сейчас у областей и районов — 1–2 предложения. Если своего текста нет, в карточке показывается описание региона уровнем выше. |
| `more` | Необязательный развёрнутый рассказ под кнопкой «Подробнее». |
| `notes` | Заметки мастера, видны всем. |

### Дороги

`data/geo/roads.geojson`: фривеи сгруппированы по номеру, улицы — по названию и разбиты на связные куски. Поля: `cls`, `id`, `ref`, `name`, `aka`, `lanes` (полос в одну сторону), `speed` (миль/ч), `toll`, `km`, `areas` (id областей по пути). Полосы и скорость — из современного OSM, в карточке это оговорено.

### Личные пометки

`localStorage`, ключ `vtm-dallas-2005-map.personal.v1`: `{"items": {"d:prestonhollow": {"marker": "…", "label": "…", "notes": "…"}}}`. `a:` — область, `z:` — часть области, `d:` — район, `s:` — сектор. Импорт понимает и файл пометок старой карты в клетку (клетка ложится на район в её центре). Выбранные режим и масштаб помнятся под `vtm-dallas-2005-map.view`.

### Ссылки

`#a/<id>`, `#z/<id>`, `#d/<id>`, `#s/<id>`, `#r/<id дороги>`. Старые ссылки `#city-D5`, `#core-B4`, `#fw-E6` открывают район в центре клетки.

## Правила для описаний

1. Всё по состоянию на весну 2005 года. Если факт не проверить, лучше не писать.
2. Описывай то, что лежит в границах региона.
3. Сейчас у областей и районов короткие описания (1–2 предложения, характер места). Подробности (`more`) — потом, когда будем копать конкретные места; материал — тексты старой карты в `data/legacy/grid-2005.json`.
4. Язык простой и живой, как у знающего друга, который объясняет мастеру из постсоветского пространства. Без канцелярита, списков, эмодзи и рекламы.
5. Названия мест транслитерируются по-русски, названия учреждений можно оставлять по-английски.
6. Никаких личных секретов игроков и закулисья мастера. Реальные люди — только исторический фон.
